# 热谱裁线台

本地 Kotlin/Ktor/SQLite 热分析复核台，用于对 DSC/TGA 导出的温度、时间、热流、质量和炉温程序进行切段、基线选择、转变热积分与质量台阶复核。原始曲线始终保留在 SQLite 中，页面只按采集段次绘制，不对缺测区间补线。

## 运行

- 构建：`mvn -q -DskipTests package`
- 测试并演示：`mvn -q test && mvn -q exec:java -Dexec.mainClass=app.MainKt -Dexec.args='--port 5518'`
- 访问：`http://127.0.0.1:5518`
- 页面标题为“热谱裁线台”。

默认数据库为 `data/thermal-bench.sqlite`。首次启动且数据库为空时自动导入固定 fixture；也可指定：

```bash
mvn -q exec:java -Dexec.mainClass=app.MainKt -Dexec.args='--port 5518 --db data/review.sqlite'
```

删除数据库文件或点击“清空并重新导入”后，可从 `src/main/resources/fixtures/*.csv` 完整重放并复核。

## 固定 Fixture

- 炉温程序：0–90 s 从 0 升到 90 °C；90–110 s 恒温；110–150 s 从 90 降到 30 °C。
- 采集段次：1 s、2 s、5 s、4 s 四种采样间隔。
- 缺测区间：60–70 s；R1 在 60 s 截止，R2 从 70 s 开始，曲线不跨这段连接。
- 重复样本：20 s、90 s、110 s 均保留同刻多行；排序为时间、仪器序号、样本 ID。
- 转变区被 60–70 s 缺测切开，两侧分别有可复核的候选转变。
- 50–60 s 与 70–80 s 的直线基线和曲线均有三次几何交点：起始锚点、一次正负穿越、终止锚点。

## 数据口径

### 切段与缺测

- 曲线先按炉温程序（升温、恒温、冷却）标记背景，再按采集段次绘制折线。
- 只有同一个已采集连续区间内的两个锚点可以计算；跨越 60–70 s 缺测会直接返回错误，不做线性补线、不积分。
- 段次首尾相接（如 90 s、110 s）不算缺测，但同刻重复样本全部保留。

### 锨点与基线

- 每个转变需要起点和终点两个锨点；可选择具体样本 ID，因而可区分同刻重复样本。
- 直线基线：按时间连接两个锨点的原始热流。
- 分段基线：经过两个锨点，并在选择范围内的炉温程序边界增加拐点；若无程序边界则退化为直线并给出提示。
- 重新选择基线或符号会生成试算结果；点击保存才新增方案，旧方案不更新、不覆盖，便于为同一转变保留两个合理边界。

### 积分

- 时间积分按时间梯形法计算：`∫(HF - baseline) dt`，原始单位为 mW·s，即 mJ；另按吸热符号口径输出 `endothermicIntegral`。
- 温度积分按温度梯形法计算：`∫(HF - baseline) dT`，单位为 mW·°C。
- 温度积分只在选择范围内温度严格单调升温或严格单调降温时有效。
- 恒温段、升温和冷却混合、或其它非一一映射的温程，不按温度直接积分；时间积分仍按连续时间数据计算。
- 本 fixture 的纯升温区间升温率为 1 °C/s，因此时间积分的 mJ 数值与温度积分的 mW·°C 数值相同，但二者含义和单位不同，页面与 API 分列显示。
- 重复样本按仪器序号参与排序；零时间宽度不产生梯形面积。

### 交点、onset、peak、endset

- 交点规则不是“取第一个交点”，而是完整枚举：
  - 两个锚点；
  - 偏差严格为零的原始样本；
  - 每对相邻非零偏差样本之间的线性插值交点；
  - 贴线接触时显式给出接触样本，避免只报告第一个交点。
- `peak` 按当前吸热符号口径选择目标方向上的最大偏差。
- `onset` 是峰值前最靠近峰值的交点，`endset` 是峰值后最靠近峰值的交点。
- API 与页面返回所有交点的时间、温度、热流和类型；页面以橙色点全部标出。

### 质量台阶

- 质量区间使用两个锨点的原始质量，返回起止时间、温度、质量、`deltaMassMg` 和相对起点的百分比。
- 跨越缺测时不计算，避免用两端数值伪造连续台阶。

## API

- `GET /api/state`：曲线、程序段、采集段次、原始样本、方案和摘要。
- `POST /api/analyze`：试算，不写库。
- `POST /api/schemes`：校验并新增不可变方案。
- `POST /api/reset`：清空曲线和方案，重新导入固定 fixture。
- `GET /api/export`：导出完整 JSON 复核包，并写入一条 EXPORT 运行记录。
- `GET /api/operations`：查看导入、保存、清空和导出记录。

## SQLite 表

- `curves`、`program_segments`、`acquisition_runs`、`samples` 保存原始 fixture。
- `samples.sample_id` 唯一；同刻重复通过不同 `sample_id` 和 `instrument_seq` 保留。
- `schemes` 保存锨点、基线类型、吸热符号、曲线摘要 JSON、算法参数 JSON、当次结果 JSON 和创建时间。
- `operation_log` 保存清空重导、方案保存和导出操作。
- `curve_summary_json` 中包含原始行数、缺测区间、重复时刻、采样率和 SHA-256 原始数据摘要。

## 测试

自动化测试位于 `src/test/kotlin/app`，覆盖：

- 时间积分与温度积分在纯升温区间的区分和数值关系；
- 恒温接冷却时温度积分无效；
- 跨越 60–70 s 缺测被拒绝，且没有积分结果；
- 同刻重复样本按仪器序号保留；
- 三个交点均可见，onset/endset 规则明确；
- 直线与分段方案分别新增，重新选择不改写旧方案；
- 清空数据库后可重新导入；
- 页面、导出包和运行记录可通过 Ktor 测试访问。
