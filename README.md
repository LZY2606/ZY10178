# 热谱裁线台

面向 DSC / TGA 实验曲线的本地裁线分析服务：按炉温程序切段、自定义基线、积分转变热、
复核质量台阶，**原始曲线只读保留，分析方案只追加不改写**。

- 技术栈：Kotlin + Ktor (Netty) + SQLite (JDBC) + 原生 Web 单页（Canvas，无前端构建）
- 固定 fixture：同时含升温 / 恒温 / 冷却三段，转变区被一个 24 s 采集断点切开，
  默认锨点区间内基线与曲线恰好三次内部相交
- 自动化测试：18 个 JUnit 5 用例，覆盖切段、断点、重复样本、交点、双积分口径、
  方案不可变、导出/清空/重放

## 运行

```bash
# 安装构建（跳过测试打包）
mvn -q -DskipTests package

# 演示：先跑测试，再启动本地服务
mvn -q test
mvn -q exec:java -Dexec.mainClass=app.MainKt -Dexec.args='--port 5518'
```

打开 <http://127.0.0.1:5518> ，页面标题为“热谱裁线台”。

可选参数：`--port 端口`、`--db SQLite文件路径`（默认 `data/thermal-bench.sqlite`）。
数据库为空时服务启动会自动导入固定 fixture；用页面底部“清空并重导 fixture”可回到初始状态。

## 数据口径（重要）

### 切段与采样率
- 炉温程序三段：升温 0–150 s（40→280 ℃，2 s/点）、恒温 150–200 s（280 ℃，1 s/点）、
  冷却 200–280 s（280→60 ℃，4 s/点）。各段采样率不同，属仪器正常设置。
- **段接缝不是断点**：相邻采样点跨越炉温程序段边界时，即使时间差较大也不计为缺测；
  只有同一段内部、采样间隔超过该段标称间隔 1.8 倍的无数据区间才判为采集断点。
- fixture 的断点在升温段 **96–120 s**（约 191–228 ℃），转变峰尾部跨过该洞。

### 缺测区间禁止补线
- 图形与积分都**不跨越缺测洞插值或连线**。
- 时间积分按洞两侧的连续 run 分别梯形求和后相加，每个 run 在结果中单独列出。
- 质量台阶取窗口两端的中位质量，跨洞时不插值。
- 洞两侧残差若异号，只登记“洞内疑似符号变化”（标记、可见），**不插值位置、不参与积分对**。

### 同时刻重复样本
- 仪器导出的同一时间戳样本按仪器序号 `seq` 全部保留，不去重、不平均；
  重复点在图上以橙色圆点标出。积分遇到 dt=0 的相邻样本时不产生面积贡献。

### 时间积分 vs 温度积分（严格区分）
- **时间积分** ∫(热流 − 基线)·dt：沿时间轴，允许跨炉温程序段（按段列出贡献），
  但不跨缺测洞。任何曲线都有定义。
- **温度积分** ∫(热流 − 基线)·dT：沿样品温度轴，仅在**单一炉温程序段且温度严格单调**
  时有效；以下情况一律判为无效并给出原因：
  - 锨点跨越多个炉温程序段（温度轴不是时间的单值映射，冷却段温度重复）；
  - 恒温段（dT=0）；
  - 段内温度出现摆动回折（非严格单调）。
- 验收可直接对比同一转变的两个积分值：二者量纲不同、数值不同，但各自可解释。

### 基线
- 直线基线：左右两个锨点取值连线。
- 分段基线：两个锨点附近 ±8 s 安静窗口分别做最小二乘直线，外推后在锨点中点打结，
  形成连续两段折线。切换基线类型只影响新结果。

### 交点规则（不以第一个交点偷换）
- 结果列出锨点区间内残差与基线的**全部**符号变化点，含两个锨点锚点、洞内疑似点；
  图上逐个标注时间/温度/符号方向。
- 用于积分边界与 onset/endset 的内部交点对，取
  **“两交点之间带符号残差面积绝对值最大”的组合**，并在结果 `crossingRule` 中明示；
  不足两个内部交点时回退为锨点本身。绝不默认取第一个交点。

### onset / peak / endset
- peak：区间内带符号残差最大点；
- onset / endset：峰两侧最陡上升/下降切线与残差零线的交点（切线外推，不跨洞）。

### 吸热正负号口径
- `ENDO_UP`：仪器曲线吸热向上（默认）；
- `ENDO_DOWN`：吸热向下，分析前对残差取负。切换口径会令积分与峰方向整体反号。

### 方案留存
- 每次“保存方案”都向 SQLite `plans` 表追加一条（请求参数 + 完整结果 JSON），
  不更新、不覆盖。对同一转变可保存“边界A/边界B”等两个合理边界。
- 页面左侧方案列表点击即可重放历史参数与结果；重新选择基线不会改写旧方案。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 操作页面 |
| GET | `/api/curve` `/api/summary` `/api/samples?segment=` | 原始曲线（只读） |
| POST | `/api/analyze` | 预览分析（不落库） |
| POST | `/api/plans` | 分析并追加保存方案 |
| GET | `/api/plans?curveId=` | 历史方案列表 |
| GET | `/api/runs` | 运行记录 |
| GET | `/api/export` | 导出曲线+方案+运行记录 JSON |
| POST | `/api/admin/reset` | 清空数据库 |
| POST | `/api/admin/load-fixture` | 清空并重导 fixture |
| POST | `/api/import` | 在空库上重放导出包（非空返回 409） |

## 清空后重新导入复核

```bash
curl -OJ http://127.0.0.1:5518/api/export           # 导出 thermal-bench-export.json
curl -X POST http://127.0.0.1:5518/api/admin/reset   # 清空
curl -X POST http://127.0.0.1:5518/api/import \
  -H 'Content-Type: application/json' --data-binary @thermal-bench-export.json
```

重放后曲线、断点数、重复样本组、各方案积分值与导出前一致（测试
`export then reset then reimport ...` 锁定该行为）。

## 存储

SQLite 表：`curves`（原始样本/程序段/摘要 JSON）、`plans`（只追加）、`run_log`（运行记录）。
